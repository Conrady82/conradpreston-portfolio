# Slice 4: JSON-LD Person schema

Closes the SEO+social roadmap theme. The remaining gap is a structured-data Person record so search engines (Google rich results, Bing, LinkedIn previews) can resolve "Conrad Preston" to a canonical entity with name, title, URL, and sameAs profile links. One small inline `<script type="application/ld+json">` injected from the root layout. No visual change, no new dependency, no runtime backend.

## Behavior
- Every page response includes one `<script type="application/ld+json">` tag in the document `<head>` whose JSON body is a valid schema.org `Person` record.
- The Person record's `name` is "Conrad Preston", `url` is `https://conradpreston.dev`, and `jobTitle` reflects the existing layout title ("Senior Software Engineer").
- The Person record includes a `sameAs` array linking to the same external profiles already shown in the site (e.g., GitHub, LinkedIn) so search engines can disambiguate the entity.
- Existing visual layout, components, and metadata are unchanged.

## Approach
Approach: define a typed `personJsonLd` constant in `app/layout.tsx` (a `Person` object literal with `@context`, `@type`, `name`, `url`, `jobTitle`, `description`, `sameAs`), then render a single `<script type="application/ld+json" dangerouslySetInnerHTML={{ __html: JSON.stringify(personJsonLd) }} />` inside `<body>` (or via `<head>` children) at the top of `RootLayout`. Source the `sameAs` URLs from links already present in components (GitHub, LinkedIn) — no new content invented. Machine-verifiable check: `npm run build` succeeds AND `curl -s https://conradpreston.dev/ | grep -c 'application/ld+json'` returns 1, with the embedded JSON parseable and containing `"@type":"Person"` and `"name":"Conrad Preston"`.
Gives up: a separate `lib/seo/jsonld.ts` module, multiple schema types (WebSite, BreadcrumbList, ProfilePage), and a generator helper. One Person record in one file is the whole SEO gap; abstraction can wait until a second schema type is actually needed.
