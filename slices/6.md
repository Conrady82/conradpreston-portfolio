# Slice 6: prefers-reduced-motion sweep — About / Projects / Skills / Contact

Closes the in-view-gated half of the Accessibility theme that slice 5 deferred. Hero and Nav already honor `prefers-reduced-motion` via `lib/useReducedMotion.ts` (slice 5). The four remaining animated components — About, Projects (header + every ProjectCard), Skills (header + every group card), Contact (header + form) — each render a `motion.*` element whose `initial`/`animate`/`transition` props are gated on `useInView`. Reduced-motion users currently still see fades/slides as content scrolls into view. This slice applies the existing hook to all four, mechanically, with no architectural change. Users without the preference set see byte-identical animations; users with it set get the final visual state on mount with zero-duration transitions.

## Behavior
- When the user agent reports `prefers-reduced-motion: reduce`, the About section eyebrow / heading / copy column / stats column render in their final visual state with no fade or slide on scroll.
- When the user agent reports `prefers-reduced-motion: reduce`, the Projects section header and every project card (production + open-source) render in their final visual state with no staggered fade-in on scroll.
- When the user agent reports `prefers-reduced-motion: reduce`, the Skills section header and every category card render in their final visual state with no staggered fade-in on scroll.
- When the user agent reports `prefers-reduced-motion: reduce`, the Contact section header and form render in their final visual state with no fade or slide on scroll.
- When the user agent does not report `prefers-reduced-motion: reduce`, every existing animation in About / Projects / Skills / Contact plays exactly as it did before this slice (no visual diff for the default audience).

## Approach
Approach: in each of the four components, call `useReducedMotion()` once at the top, then for every `motion.*` element compute `initial`, `animate`, and `transition` conditionally — when reduced is true, pass `initial={false}` and `transition={{ duration: 0 }}` so the element renders directly in its `animate` target state without a visible transition. Where a child component (`ProjectCard` in Projects.tsx) currently receives `inView` only, accept a second `reduced: boolean` prop rather than calling the hook per-card, to keep matchMedia subscriptions to one per section. Machine-verifiable check: `npm run build` and `npm run typecheck` exit 0, and a grep of the four component files confirms each `motion.` element either references the hook or the boolean derived from it.
Gives up: a global `MotionConfig` provider, refactoring the four components to share a single animated-section wrapper, and any framer-motion v12 built-in reduced-motion API. The duplication across four files is small and the changes are mechanical; abstracting now would obscure the pattern slice 5 established.
