# Slice 2: Minimal CI — typecheck + build on every PR and push

Add a GitHub Actions workflow that runs `tsc --noEmit` and `next build` on pull requests and pushes to `main`. This is the foundation that gates every subsequent slice (sitemap, JSON-LD, Lighthouse CI, web-vitals, a11y, contact route): regressions get caught at PR time instead of at deploy or never. No app code touched, no visual change, reversible by reverting one commit.

## Behavior
- A push to `main` triggers a CI workflow that runs typecheck and build; both must pass for the workflow to be green.
- A pull request targeting `main` triggers the same CI workflow; the workflow appears as a required-status candidate on the PR.
- The CI workflow installs dependencies deterministically using the lockfile and Node 20.
- A TypeScript error introduced anywhere under `app/` or `components/` causes the workflow to fail.
- A broken `next build` (e.g., missing import, runtime-time crash during prerender) causes the workflow to fail.
- `npm run typecheck` exits 0 locally on the current tree.
- `npm run build` continues to exit 0 (slice 1 invariant preserved).

## Approach
Approach: a single workflow file `.github/workflows/ci.yml` with one job `verify` running on `ubuntu-latest`, Node 20 via `actions/setup-node@v4` with `cache: 'npm'`, `npm ci`, then two sequential steps: `npm run typecheck` and `npm run build`. Add `typecheck` to `package.json` scripts as `tsc --noEmit` so the same gate runs locally. Triggers: `pull_request` against `main` and `push` to `main`. No matrix, no caching beyond setup-node's built-in npm cache, no artifact upload — keep the surface tiny so future slices (Lighthouse CI as a separate job, Playwright smoke as a separate job) can extend without rewriting.
Gives up: a polished multi-job pipeline (lint, format, test matrix across Node versions, concurrency cancellation, coverage upload). All of those are worth doing; none are worth doing in slice 2. The point is the foundation.
