# Slice 1: Complete OpenGraph + Twitter card + canonical + robots metadata

Tighten the `<head>` so social shares render a real preview card and crawlers see canonical/robots directives. Pure-static metadata change in `app/layout.tsx` plus one image asset; no new routes, no runtime backend, no visible layout change. Reversible by reverting one commit.

## Behavior
- A request to the site's HTML returns an `og:image` meta tag pointing at a 1200x630 image hosted on the same origin.
- A request to the site's HTML returns a Twitter `summary_large_image` card with title, description, and image.
- A request to the site's HTML returns a canonical link tag set to `https://conradpreston.dev`.
- A request to the site's HTML returns a robots meta directive of `index, follow`.
- Existing OpenGraph tags (title, description, url, siteName, type) remain present and unchanged in value.
- `npm run build` exits 0 and produces a static prerender for `/`.

## Approach
Approach: extend the existing Next.js `Metadata` export in `app/layout.tsx` with `metadataBase: new URL("https://conradpreston.dev")`, `alternates: { canonical: "/" }`, `robots: { index: true, follow: true }`, a `twitter` block (`card: "summary_large_image"`, title, description, images), and `openGraph.images: [{ url: "/og-image.png", width: 1200, height: 630, alt: ... }]`. Add a single 1200x630 `public/og-image.png` asset. Verification is `npm run build` followed by grep against the prerendered HTML at `.next/server/app/index.html` for each required tag.
Gives up: programmatic OG image generation via `app/opengraph-image.tsx` / `next/og`. Static PNG is simpler, faster to build, and easier to swap.
