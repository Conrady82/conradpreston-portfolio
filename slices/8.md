# Slice 8: Playwright smoke test — page renders, all sections present

Add a single Playwright smoke test that boots `next start` against the production build, loads `/`, and asserts the page rendered with all expected sections, the canonical link, and the Hero headline. Wires it into a third CI job named `smoke` alongside `verify` and `lighthouse`. First-class quality gate against "page silently broke" regressions; foundation for any future UI assertion. No visual snapshots (flaky), no per-component coverage (over-engineering for a single-page site), no auth/state. One URL, deterministic asserts on stable text and ids.

## Behavior
- A pull request to `main` runs a third CI job named `smoke` in addition to `verify` and `lighthouse`; all three jobs run independently.
- The `smoke` job builds the site, starts `next start` on port 3000, waits for the server, and runs a Playwright test against `http://localhost:3000/`.
- The smoke test asserts the page returns HTTP 200 and the `<h1>` contains "Senior Software Engineer".
- The smoke test asserts each section anchor (`#about`, `#projects`, `#skills`, `#contact`) is present in the DOM.
- The smoke test asserts `<link rel="canonical" href="https://conradpreston.dev/">` is present in the rendered head.
- A regression that crashes `next start`, removes a section id, removes the canonical link, or empties the Hero h1 fails the `smoke` job.
- Developers can reproduce CI locally via `npm run test:smoke` (assumes a running `next start`) or `npm run test:smoke:ci` (builds + starts + tests + tears down).

## Approach
Approach: install `@playwright/test` as a devDependency. Create `playwright.config.ts` at repo root with a single project (chromium-only — single browser is sufficient for "page renders" assertions and keeps install fast in CI), `baseURL: 'http://localhost:3000'`, `testDir: 'tests'`, no `webServer` config (CI manages the server in the workflow step, mirroring the lighthouse job's pattern for parity and observability). Write `tests/smoke.spec.ts` as a single `test('page renders all sections', ...)` block that does `goto('/')`, asserts response status 200, then asserts each anchor via `page.locator('#about')` etc., the h1 text via `page.getByRole('heading', { level: 1 })`, and the canonical link via `page.locator('link[rel="canonical"]')` attribute check. Add a third job `smoke` to `ci.yml`: checkout, setup-node 20, `npm ci`, `npx playwright install --with-deps chromium`, `npm run build`, start `next start` in background, poll for readiness (reuse the lighthouse pattern), `npx playwright test`, kill server.
Gives up: multi-browser (Firefox/WebKit) coverage (one browser proves the page renders; the rest is duplicate slow surface), visual regression snapshots (flaky on a Framer-Motion site, defeats the "page renders" goal), test sharding (one test, no need), Playwright trace upload as workflow artifact (useful but adds touch-list weight; can be added in a follow-up slice if smoke flakes), local Playwright cache action (premature optimization for a 1-test suite).
