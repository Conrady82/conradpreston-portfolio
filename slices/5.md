# Slice 5: prefers-reduced-motion respect for Framer Motion

Opens the Accessibility roadmap theme. Users with `prefers-reduced-motion: reduce` set at the OS level (a vestibular/cognitive accommodation) currently receive the full Hero entrance animation and Nav mobile-menu slide. Framer Motion does not honor the media query by default. This slice introduces a single shared hook and applies it to the two unconditional, always-on-mount animation surfaces (Hero, Nav). In-view-gated components (About/Projects/Skills/Contact) animate only once on scroll and are deferred to a follow-up — they are less harmful for affected users than the Hero burst. No visual change for users without the preference set; users with it set see static content with normal opacity instead of fades/slides.

## Behavior
- When the user agent reports `prefers-reduced-motion: reduce`, Hero renders its eyebrow / name / tagline / CTA buttons in their final state with no entrance animation (no fade, no slide).
- When the user agent reports `prefers-reduced-motion: reduce`, the Nav mobile menu opens and closes by toggling visibility only (no slide-down / fade transition).
- When the user agent does not report `prefers-reduced-motion: reduce` (or the preference is absent), all existing animations play exactly as they did before this slice.
- The `prefers-reduced-motion` decision is made via one shared hook so future motion sites can opt in identically.

## Approach
Approach: implement `lib/useReducedMotion.ts` as a small client hook that returns a boolean from `window.matchMedia('(prefers-reduced-motion: reduce)')`, defaulting to `false` during SSR and subscribing to `change` events for runtime preference flips. In `Hero.tsx` and `Nav.tsx`, call the hook once at the top of the component and conditionally pass either the existing motion props or a reduced variant (`initial={false}`, `transition={{ duration: 0 }}`) so the final visual state is preserved but transitions are skipped. Machine-verifiable check: `npm run build` succeeds, `npm run typecheck` succeeds, and a curl/grep of the built `.next` HTML confirms Hero text content is statically present in the rendered output. The hook itself is unit-testable by stubbing `window.matchMedia`.
Gives up: a global `MotionConfig` provider wrapping the entire layout, a sweep across all five animated components in one slice, and any `framer-motion`-version-specific built-in reduced-motion API. Two surfaces in one slice is the right blast radius; the in-view components can be brought in line in a follow-up slice once this hook is proven.
