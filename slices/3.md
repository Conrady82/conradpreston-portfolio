# Slice 3: robots.txt + sitemap.xml — basic crawler hygiene

Tell crawlers (a) they may index the site and (b) where the canonical URL lives. Slice 1 added the canonical/robots meta tags inside the HTML; this slice publishes the two well-known machine-readable endpoints crawlers actually fetch first. Pure-static, generated at build time by Next.js App Router file conventions (`app/robots.ts`, `app/sitemap.ts`). No new routes for users, no visual change, reversible by reverting one commit.

## Behavior
- A request to `/robots.txt` returns `200` with a body that allows all user agents and points `Sitemap:` at `https://conradpreston.dev/sitemap.xml`.
- A request to `/sitemap.xml` returns `200` with valid XML containing exactly one `<url><loc>https://conradpreston.dev</loc>` entry.
- Both endpoints are statically prerendered by `next build` (no serverless invocation per request).
- Existing canonical/og/twitter/robots meta tags from slice 1 remain unchanged.
- `npm run build` exits 0 and `npm run typecheck` exits 0 (slice 1 + 2 invariants preserved).

## Approach
Approach: use Next.js App Router's built-in `MetadataRoute.Robots` and `MetadataRoute.Sitemap` file conventions. `app/robots.ts` exports a default function returning `{ rules: [{ userAgent: "*", allow: "/" }], sitemap: "https://conradpreston.dev/sitemap.xml" }`. `app/sitemap.ts` exports a default function returning a single-entry array `[{ url: "https://conradpreston.dev", lastModified: new Date(), changeFrequency: "monthly", priority: 1 }]`. Both are statically generated at build time because they have no dynamic input. The canonical origin string is duplicated (also lives in `app/layout.tsx`); accepted as-is for slice 3 — extracting a shared constant is its own cleanup slice if the duplication ever bites.
Gives up: per-section anchors in the sitemap (`/#about`, `/#projects`, etc.). The site is single-page; fragment URLs are not separately indexable and would mislead crawlers. Also gives up dynamic `lastModified` from git mtime — `new Date()` at build time is good enough and the CI rebuilds on every push.

## Machine-verifiable check
Locally, after `npm run build`:
- `test -f .next/server/app/robots.txt.body` (Next emits the static body alongside the route handler) OR `curl -fsS http://localhost:3000/robots.txt | grep -q 'User-[Aa]gent: \*'` against `npm start`.
- Static-asset path check (preferred, no server needed):
  - `find .next -name 'robots.txt*' -print | grep -q .`
  - `find .next -name 'sitemap.xml*' -print | grep -q .`
- Behavioral check via a one-shot `npm start &` + `curl`:
  - `curl -fsS http://localhost:3000/robots.txt | grep -Eq '^User-[Aa]gent:\s*\*'`
  - `curl -fsS http://localhost:3000/robots.txt | grep -q 'Sitemap: https://conradpreston.dev/sitemap.xml'`
  - `curl -fsS http://localhost:3000/sitemap.xml | grep -q '<loc>https://conradpreston.dev</loc>'`
  - `curl -fsS http://localhost:3000/sitemap.xml | xmllint --noout -` (well-formed XML; xmllint is preinstalled on macOS and ubuntu-latest)
- `npm run typecheck` exits 0
- `npm run build` exits 0
